[Презентация](https://docs.google.com/presentation/d/13YYXzz257Jhe6Nnalj6CcwmOXL8Y58ODuKg4mw_QbnI/edit?usp=sharing)

CodeClarity — локальный плагин Codex для ревью читаемости **Java- и Python-изменений между Git-коммитами**. Он объединяет AI-анализ исходников с измеримыми характеристиками кода и сохраняет отчёт с замечаниями, ссылками на строки и рекомендациями.

Готовая версия **0.4.0** находится в [plugin/](plugin/). [Документация плагина](plugin/README.md) · [Установка и обновление](plugin/INSTALL.md).

## Какие метрики анализируются

Для изменённых функций и методов сравниваются значения **до и после изменения**, а также их разница.

| Метрика | Что показывает |
|---|---|
| Cyclomatic Complexity | Количество независимых путей выполнения |
| Cognitive Complexity | Структурную сложность понимания потока управления |
| SLOC | Количество строк исходного кода функции или метода |
| Максимальная вложенность | Глубину вложенных управляющих конструкций |
| Количество параметров | Размер списка параметров функции или метода |
| Количество возвратов | Число операторов `return` |

Метрики помогают обосновать замечания. Проблемы с именами или абстракциями могут сохраняться и при небольших значениях сложности.

## Как проходит ревью

1. **Выбор изменений.** Пользователь задаёт репозиторий и Git-диапазон. Сервер определяет изменённые файлы и Git-снимки для сравнения.
2. **Независимое чтение.** Агент изучает обе версии кода, ищет проблемы читаемости и сохраняет наблюдения до получения метрик.
3. **Измерения.** Локальный MCP-сервер рассчитывает шесть метрик: для Java используются PMD и JavaParser, для Python — AST и complexipy.
4. **Сопоставление.** Агент объясняет, какие измерения поддерживают замечания, и отмечает недоступные данные и пропуски анализа.
5. **Отчёт.** Результат сохраняется в JSON и Markdown: замечания, исходные строки, рекомендации и сравнение метрик. Статусы: `PASS` — полное ревью без замечаний, `WARN` — полное ревью с обоснованными замечаниями, `INCOMPLETE` — ревью неполное.
6. **История и правила.** Ревью сохраняется в истории проекта. Повторяющиеся проблемы и подтверждённые исправления могут стать основанием для предложения правила со статусом `PROPOSED`. Подтверждения исправлений записывает оператор.

## Что делает каждый Skill

| Skill | Роль |
|---|---|
| `readability-review` | Управляет полным процессом: выбирает область ревью, запускает этапы и собирает итоговый отчёт |
| `independent-review` | Анализирует имена, структуру и понятность исходников до просмотра метрик |
| `metrics-correlation` | Сопоставляет независимые наблюдения с фактическими измерениями и обосновывает выводы |
| `rule-discovery` | Сохраняет ревью в истории и предлагает правила по повторениям и внешним подтверждениям исправлений |

## Основные папки

- **`src/`** — MCP-сервер, анализаторы Java/Python и хранение истории.
- **`plugin/`** — готовая поставка: Skills, сервер, контракты данных, средства запуска и документация.
- **`scripts/`** — сборка установочного архива и проверки проекта.
- **`evals/`, `experiments/`** — проверочные сценарии, примеры кода и результаты запусков.

Для установки нужны локальный Codex с поддержкой плагинов, JDK 21+, Git и Python 3.10+ с `complexipy==8.3.0`.
