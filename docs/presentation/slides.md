# CodeClarity: шесть слайдов для демонстрации

Состояние анализаторов: `feature/python`, `ec6a3ed`. LLM-срез: установленный CodeClarity 0.2.0 и фактический запуск Codex CLI. Презентация отдельно обозначает целевое поведение и наблюдаемые результаты. Продолжительность: около 4 минут.

## 1. CodeClarity

Читаемость изменений Java и Python. Разработчик получает объяснение проблем до ревью человеком.

Заметки: AI помогает писать код, а команде нужно понять его назначение и стоимость сопровождения. CodeClarity проверяет Git-изменения. Не объявлять весь MVP завершённым на основании существования плагина.

## 2. Короткий код тоже требует ревью

Иллюстрация, не результат выполненного Eval:

```python
def f(items):
    return [item for item in items
            if item.is_active]
```

Наблюдение: имя `f` не объясняет назначение. Минимальная рекомендация: `select_active_items`. Сначала независимое наблюдение, затем измерения из MCP. Численные значения для этой иллюстрации не утверждаются.

## 3. Порядок проверки

1. Git snapshots: scope, SHA, исходники.
2. Independent Review: находки до текущих метрик.
3. MCP metrics: шесть метрик и статусы доступности.
4. Metrics Correlation: связь чисел с наблюдениями.
5. Report: JSON, Markdown, доказательства, вердикт.
6. Rule Discovery: история и кандидат правила.

Локальный Java 21 Core и MCP STDIO. Skills разделяют этапы логически в одном контексте Codex. LSP опционален.

## 4. Шесть метрик MVP

| Метрика | Java | Python |
|---|---|---|
| Cyclomatic complexity | PMD | Собственный AST-алгоритм |
| Cognitive complexity | PMD | `UNSUPPORTED` |
| Function SLOC | Ожидает Core | Ожидает Python |
| Max nesting depth | Ожидает Core | Ожидает Python |
| Parameter count | Ожидает Core | Ожидает Python |
| Return count | Ожидает Core | Ожидает Python |

Состояние соответствует `ec6a3ed`. Все числа поступают из MCP/Core. Delta требует доступных значений и совместимых версий алгоритма. Return count не создаёт самостоятельную ошибку.

## 5. Rule Discovery

Начальная эвристика: не менее трёх отдельных обнаружений одной категории, не менее двух исправлений с внешним подтверждением, нет эквивалентного предложенного правила.

Результат: кандидат `PROPOSED`, примеры и исключения. Человек принимает решение об активации. Без оснований Skill не выводит предложение.

Заметки: история для показа синтетическая. Числа здесь задают эвристику, а не статистику пользователей. Оба сценария решения Skill прошли forward Evals, но не проверяют persistence через Core. Статический `RESOLVED` не доказывает подтверждённый человеком `FIXED`. Запись истории принадлежит Core. В фактическом запуске history MCP Tools отсутствуют и Rule Discovery имеет статус `UNAVAILABLE`.

## 6. Фактический запуск Codex

Установленный CodeClarity 0.2.0 обнаруживает четыре Skills. На смешанном Java/Python примере Codex CLI сделал восемь реальных MCP-вызовов: два `list`, четыре `inspect`, два `analyze`.

Независимый артефакт зафиксирован на JSONL eventIndex 37, первые анализы начались на 38 и 39. Отчёт содержит две обоснованные AI-находки: вложенные Java guards (`SUPPORTED`) и непрозрачные имена Python (`UNRELATED`).

Измерения Java от PMD: CC до 1, после 7, delta 6. CogC до 0, после 21, delta 21. В Python изменение сигнатуры `subtotal(line_items)` на `subtotal(a)` разрывает сопоставление, поэтому численная delta отсутствует. Шесть записей сравнения в отчёте не означают шесть реализованных видов метрик.

Шесть forward Evals прошли: четыре сценария кода с реальным JAR, два решения на явно синтетической истории. Финальный вердикт запуска `INCOMPLETE`: обязательные метрики ещё отсутствуют. История `UNAVAILABLE`. Совместная репетиция `NOT_RUN`.

Заметки: один живой прогон не доказывает детерминированность поведения модели. Открываем фактические протоколы из `evals/results/codex-live.json` и `evals/results/agent-forward.json`. Резервный показ использует сохранённые результаты с их реальными статусами. Persistence, feedback и полный MVP E2E ещё требуют интеграции с Core.
