## Что уже реализовано

- Один MCP-сервер с Java- и Python-адаптерами, общий Git-слой и Core.
- Python 3.10+, стандартный `ast`; проверяемый код не импортируется и не исполняется.
- `.py` в UTF-8. Синтаксис определяется выбранным интерпретатором.
- Обычные и async-функции, методы классов, вложенные именованные функции.
- Диапазоны с декораторами и синтаксические ключи с цепочкой владельцев и параметрами.
- Выбор затронутых сущностей по диапазонам diff обеих версий.
- Cyclomatic Complexity: численное значение для каждой извлечённой функции;
  предупреждение `PythonCyclomaticComplexity` при значении от 10.
- Cognitive Complexity: явный `UNSUPPORTED`, без подстановки нуля.
- Общий контракт определений и значений метрик, сравнение до/после и дельта только
  при двух доступных значениях с совпадающим определением.
- Состояния `AVAILABLE`, `UNSUPPORTED`, `MISSING`, `ERROR`, `ENTITY_ABSENT`.
- Синтаксическая ошибка и отсутствие Python отражаются в предупреждениях/частичном отчёте.
  Ошибка Python не блокирует Java-анализ.
- Инспекция: вызовы тела и лексические ветви if, максимум 100 вызовов;
  выражения и условия сокращаются до 200 символов.

## Текущий алгоритм Cyclomatic Complexity

Определение: `codeclarity/python-cyclo/v1`, анализатор `codeclarity-python-ast/1`.
Подсчёт начинается с 1 и добавляет:

- 1 за if, условное выражение, for/async for, while, except и assert;
- число операндов минус 1 за and/or;
- 1 за каждый генератор comprehension и 1 за каждый его фильтр if;
- 1 за каждый case, кроме безусловного capture/wildcard, и 1 за guard case.

Тела вложенных функций, классов и лямбд исключены из подсчёта родительской функции.
Это собственный алгоритм; эквивалентность Radon, PMD или другого анализатора не проверялась.
Прохождение существующих тестов подтверждает проверенные случаи, а не все возможные конструкции Python.

## Ограничения и задачи для дальнейших этапов

| Наблюдение | Следствие | Где решать |
|---|---|---|
| Пять из шести требуемых численных метрик отсутствуют | Полное ТЗ пока не выполнено | Этапы 2–4 |
| SLOC нельзя получить простым вычитанием координат AST | Нужны правила для docstring, комментариев, декораторов и многострочных выражений | Этапы 2–3 |
| elif представлен вложенным If в orelse | Глубина дерева AST не равна требуемой глубине управления | Этапы 2–3 |
| Ключ включает имена и виды параметров | Изменение параметров разрывает точное сопоставление; дельта Parameter Count может быть недоступна | Этап 5, согласование с Core |
| Переносы функций между файлами и переименования автоматически не сопоставляются | Нельзя обещать дельту для любого рефакторинга | Сохранить явное ограничение P0 |
| Одинаковые ключи могут быть неоднозначны, например у повторных объявлений | Core возвращает предупреждение и ошибочное состояние метрик | Добавить адресные Python-сценарии на этапе 6 |
| `Version.metric()` в Core при `complete=false` помечает ошибочными все метрики версии | Для complexipy нужно отделить ошибку вычислителя от ошибки разбора, сохранив другие измерения | Этапы 4–5 |
| Анализ ограничен функциями; модульный код и лямбды не выделяются как сущности | Изменение на уровне модуля может не дать ни одной функции в отчёте | Документировать область P0 |
| Контекст не включает ранние выходы, циклы и match как условия достижимости | Это синтаксическая инспекция, не полноценный анализ потока управления | За пределами текущего P0 |
| Источник Git-снимков общий, но комплексного LSP-контекста коммита нет | Pyright нельзя подключать к случайной текущей рабочей версии зависимостей | Отдельный P1 |
| Нет единой команды для всего набора проверок | Текущее ТЗ по единому запуску ещё не закрыто | Этап 6 |

Аннотации и значения параметров по умолчанию не входят в ключ. Декораторы входят
в диапазон, но их вызовы и вызовы из значений по умолчанию не входят в инспекцию тела.
Лимиты текущей реализации: 50 выбранных файлов за вызов, 250 000 символов на исходник,
15 секунд и 4 МиБ вывода Python-процесса. При расширении worker нужно учитывать,
что его код передаётся в аргументе командной строки через Base64, а не отдельным файлом.

## Пробелы подтверждения

- Проверено одно окружение: Windows, Python 3.13.1 и JDK 25 с компиляцией под Java 21.
  Python 3.10–3.12, другие ОС и runtime JDK 21 отдельно не проверялись.
- Нет независимого сравнения собственного CC с внешним эталоном; сначала нужно выбрать
  требуемое определение алгоритма, поскольку различия не обязательно являются ошибками.
- Тесты не подтверждают шесть метрик: пять пока не реализованы.
- Текущие тесты проверяют async-выделение; дополнительные пробы подтвердили CC для async.
  Нужны отдельные постоянные сценарии async for/with и сочетаний конструкций.
- Нужны отдельные сценарии повторных имён, изменения сигнатур, удаления функций
  и изменения только комментариев в Python-коде.
- complexipy и Pyright на этом этапе не устанавливались и не оценивались исполнением.
